# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Python "what-if" emulator for AndroidAPS (AAPS). `software/determine_basal.py` is a statement-by-statement port of the oref1 SMB `determine-basal.js` as used by AAPS, plus the autoISF fork, in one file. The emulator replays each historical loop run inside a time window with its original inputs but modified settings from a variant definition file (`.vdf`; legacy `.dat` also accepted) and reports how the loop decision (insulinReq, SMB, TBR) and the effective ISF would have differed: a semicolon-separated CSV plus a PDF (one page per loop with the `pred` option; a flowchart of the decision path is a panel on those pages when `flowchart` is on). It cannot simulate the glucose response to different insulin, only the decisions.

Fork of ga-zelle's emulator (documented upstream: github.com/ga-zelle/AAPS-Emulator; the only git remote here is this fork, public on GitHub). Upstream changes arrive as whole-file re-uploads through the GitHub web UI, so taking an upstream update means diffing whole files against `software/*.py`, not cherry-picking commits.

Branches:
- `A3.4.0.0-ai3.2.0` (origin/HEAD): targets AAPS 3.4.x + autoISF 3.2, reads AAPS logfiles (older 2.x/3.3 formats still parse).
- `nightscout-source`: a Nightscout server as alternative input source, selected per run by passing a URL or `ns:` as the first argument. Logfile replay keeps working on this branch. The user's personal AAPS preferences and Nightscout URL are committed on purpose (`ns_settings.json`, `aaps_preferences.json`); secrets are not (see the Nightscout bullet below).

## Environment and commands

No packaging, no test runner, no linter, no CI; the checks are the `ns_*` `--validate` self-tests and the "no change" replay described below. The scripts import each other as plain siblings (no package). The commands below assume cwd = `software/`; the VDF path decides where results go.

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # nightscout-source only; on A3.4.0.0-ai3.2.0: pip install matplotlib
cd software
```

`requirements.txt` gives lower bounds for matplotlib and numpy; only matplotlib is imported, lazily inside `XYplots()`, so a `noplot` run needs neither. `ns_prefs_import.py` additionally needs `cryptography` for encrypted exports.

Batch run. Three positional arguments are required (no argparse; fewer raise IndexError):

```bash
PYTHONUTF8=1 ../.venv/bin/python emulator_batch.py '<logfile glob>' '<options>' <variant.vdf> [<start UTC> [<end UTC>]]

# AAPS logfiles (.zip or .log, names in the AndroidAPS._YYYY-MM-DD_... layout). Quote the glob: the core expands it.
PYTHONUTF8=1 ../.venv/bin/python emulator_batch.py '/path/aapsLogs/AndroidAPS._2026-09-06_*' 'All/-pred/-flowchart/.' variants/no_change.vdf 2026-09-06T06:00:00Z 2026-09-06T12:00:00Z

# nightscout-source: a http(s) URL, or "ns:" (= nightscout.url from ns_settings.json), replaces the glob.
PYTHONUTF8=1 ../.venv/bin/python emulator_batch.py ns: 'bg/iob/ISFs/insReq/SMB/basal/.' variants/no_change.vdf 2026-09-06T06:00:00Z 2026-09-06T12:00:00Z

# parameter sweep (nightscout-source): grid JSON -> one generated VDF per combination -> results/<label>/summary.csv
../.venv/bin/python emulator_optimize.py --grid variants/grid_autoISF.json --start 2026-09-06T00:00:00Z --end 2026-09-07T00:00:00Z
```

- `<options>` is a `/`-separated token list, unknown tokens are ignored. `All` enables every token, `-token` excludes one. Tokens are the literals tested by `featured()` in `emulator_core.py` after `_` is turned into a space (`bg`, `iob`, `cob`, `ISFs`, `insReq`, `SMB`, `basal`, `pred`, `flowchart`, `LIST`, `acce ISF`, ...). Several features are tested under two aliases OR'd together (`acce ISF`/`acce`, `pp ISF`/`pp`, `dura ISF`/`dura`, `ISF`/`ISFs`, ...), so under `All` you must exclude both. `PDF` does not control the PDF file; it only pops an interactive matplotlib window in batch mode, and not when `pred` is on. `noplot` (nightscout-source) skips `XYplots()` entirely, i.e. PDF and the `LIST` console table; it is opt-in only and NOT enabled by `All`. The GUI's default preset is `All/-pred/-flowchart/LIST`, its `All` radio gives `All/LIST`.
- In the batch front end a `.` anywhere in the option string selects `.` as the decimal symbol for the CSV, the `.delta` file and console tables; otherwise `,`. The GUI has a radio button for it.
- Start/end labels are UTC ISO strings. For logfiles they are compared lexically against each loop's `deliverAt`, so a prefix such as `2026-09-06T12` works and the defaults (`2000-...`/`2099-...`) mean open. For Nightscout each bound is defaulted separately: open end = now, open start = 24 h before the end, so a given start with open end replays start..now.
- `PYTHONUTF8` must be exactly `1` or `parameters_known()` returns the sentinel `UTF8` and nothing runs. On `nightscout-source` `emulator_batch.py` defaults it itself (`os.environ.setdefault`); on the other branch and for the GUI you must export it. Whenever `sys.platform == 'linux'` (Linux and QPython alike) both front ends also append `export PYTHONUTF8=1` to `~/.bashrc` at import time, every start, without checking.
- GUI: `python3 emulator_GUI.py` (no arguments; logfiles only, no Nightscout mode) needs a Tk-enabled interpreter that also has matplotlib.
- Phone: `emulator_batch.py` switches into an interactive QPython mode (menus, spoken alarms, endless re-scan of the live `AndroidAPS.log`) solely because it finds a non-empty AAPS log folder under `/storage/emulated/0`; it then reads no argv, and the `.vdf` plus a `*.config` file (alarm hours, table columns) must lie in that folder. Not reachable on a PC.
- Nightscout helpers (`nightscout-source`): `python ns_client.py <url|ns:> <start> <end> [entries|treatments|devicestatus ...]` prefetches into `software/ns_cache/<host>/<collection>/<YYYY-MM-DD>.json` plus `profile/all.json`, using the token/api-secret from `ns_settings.json` when given `ns:` or the settings URL; `--refresh` re-downloads the days of the window. `python ns_source.py <start> <end> [url]` dumps the first reconstructed loop input set. `python ns_iob.py|ns_glucose.py|ns_profile.py --validate <start> <end>` compare a module against `devicestatus` ground truth (run after touching a module; expect ~100% agreement, numbers in `NIGHTSCOUT_SOURCE.md`). `python ns_prefs_import.py <AAPS export.json> [--password <pw>]` (or `AAPS_EXPORT_PASSWORD`) decrypts an AAPS preferences export, writes the scrubbed `aaps_preferences.json` and rewrites only the mapped keys of `ns_settings.json`, so hand edits elsewhere survive a re-import; `--no-settings` writes only the scrubbed file. Never commit the raw decrypted export (Nightscout token and other secrets).

Results are written into the directory part of the VDF argument (a bare `no_change.vdf` lands in the cwd; never next to the logfiles): `<base>.<variant>.csv|.delta|.log|.txt|.pdf` plus `<base>.orig.txt` (the original decisions, shared by every variant of that `<base>`). `<base>` is the first logfile's full basename whenever the start label begins with `2000`, otherwise the start label with `:` replaced by `-` (`nightscout` for a Nightscout run with open start). The PDF is only written when loops were found and `noplot` is off. CSV and PDF are deleted before rewrite; the logfile scanner and `XYplots()` retry every 10 s on `PermissionError` (a viewer holding the file), `scanNightscout()` ignores it. `.gitignore` covers `.venv/`, caches, `software/results/`, `software/ns_cache/`, `*.orig.txt`, `*.delta` and result files under `software/variants/`, so a VDF elsewhere leaves untracked `.csv/.log/.txt/.pdf` behind.

The regression check is the **"no change" replay**: an empty VDF (`variants/no_change.vdf` on `nightscout-source`; any empty `.vdf` elsewhere) should reproduce the original insulinReq, SMB, rate and ISF for the large majority of loops. Compare the `orig`/`emul` column pairs in the CSV (labels in the third header row; ISF is an `orig; prof; emul` triple). Note `setVariant()` still injects emulator defaults such as `new_parameter['SMBRatio'] = 0.5001` for an empty file, so "no change" means "no VDF rows", not byte-identical inputs. Nightscout replays drop loops without `suggested.reason`/`deliverAt`, loops AAPS aborted (no `bg`/`predBGs`) and loops without a CGM entry within 12 min; the counts are printed once at the end, which explains loop count vs devicestatus count.

## Architecture

Call chain, all synchronous in one process (`nightscout-source`-only pieces marked NS):

```
emulator_batch.py / emulator_GUI.py     build the argument strings + version banner, set_tty(printframe, txtbox, channel)
  └─ emulator_core.parameters_known()   reset the per-loop lists, pre-scan the VDF, glob logfiles or pick Nightscout
       ├─ scanLogfile()                       per logfile; opens <base>.<variant>.csv, .orig.txt, .log on the first one
       │    ├─ get_glucose_status()           'Glucose status:' line opens a loop (newLoop=True) on every AAPS version
       │    ├─ pre-3.3 logs: get_iob_data / get_currenttemp / get_profile / get_meal_data / get_autosens_data
       │    │                per line, PrepareSMB() for console.error lines, then TreatLoop() on the result record
       │    └─ 3.3+ logs:    TreatLoop33() on the one '[PersistenceLayerImpl$insertOrUpdateApsResult$2.apply():' line
       │                     -> same collectors on its embedded JSONs, scanConsoleError(), then TreatLoop()
       ├─ scanNightscout()  NS                per window: ns_source.NightscoutSource.loops() -> apply_glucose_status(),
       │                                      the same collectors on json.dumps() of each loop dict, scanConsoleError(), TreatLoop()
       │    └─ TreatLoop()   once per original result record
       │         ├─ record the ORIGINAL decision      -> orig* lists (insulinReq, SMB/maxBolus scraped from the reason text, basal, cob)
       │         ├─ setVariant(stmp)                  reset new_parameter + missing profile keys, re-read the VDF, eval() each recognised row
       │         ├─ detSMB.determine_basal(..., thisTime, Fcasts, Flows, emulAI_ratio)     (import determine_basal as detSMB)
       │         └─ echo_rT() -> emulInsReq/emulBasal; reason text -> emulSMB/emulMaxBolus; Fcasts -> emulISF & co
       └─ write CSV rows and .delta, then XYplots() (matplotlib -> PDF, flowchart panels, LIST table) unless Android or noplot (NS)
```

- **Two front ends, one entry point.** Both call `parameters_known(myseek, arg2, variantFile, startLabel, stoppLabel, entries, msg, my_dec, oldPauseCarbsReqEnds)` and get an 8-tuple back whose second element is the last loop label or a sentinel: `SYNTAX` (a VDF row failed to eval during a loop), `UTF8`, `Z` (no files matched, fewer than two loops, or the VDF failed already in the pre-scan). `arg2` is the option string prefixed with `Windows/` (PC) or, built by the phone branch from the `.config` file, `Android/`; the core derives `isAndroid` from that prefix, not from the platform. Status messages go through `log_msg()`/`sub_issue()`, which `set_tty()` routes to `print` or the Tk text box (bare `print()` remains for the VDF pre-scan error and `ns_client` fetch progress). Calling the core without `set_tty()` first raises NameError.
- **Everything is module-global state** in `emulator_core.py`: the input dicts (overwritten by the collectors and `setVariant`), `newLoop`, `AAPS_Version` (`'<2.7'`; `'2.7'` for 2.7 through 3.2; `'3.3'` for 3.3, 3.4 and Nightscout) and dozens of per-loop lists that must stay aligned with `loop_mills` (each collector appends or overwrites depending on the current length; `XYplots` pops leftovers). Adding a per-loop series means touching the collector, the reset block in `parameters_known`, the CSV writer, the pop list in `XYplots` and the plot. `parameters_known` re-initialises everything, so sequential calls in one process (the optimizer) are fine.
- **Logfile parsing** (logfile path only) keys on AAPS's line layout `HH:MM:SS.mmm [thread] [Class.method():line]: message` and on padded message prefixes such as `'IOB data:       '`, which are deliberately ignored on 3.3+ because the persistence line carries the same data. Zipped logs are read through `str(bytes)`, which is why two places (`extractResultComponent`, `TreatLoop`) delete the character before the first apostrophe and why `out_units` arrives as `mmol\/L` from zipped logs but `mmol/L` from plain logs and Nightscout (`convert_bg()` strips the backslash; the `== 'mmol/L'` test in the half-basal-target branch of `determine_basal.py` does not). Log-line headers are phone local time; ISO strings inside the JSON are treated as UTC.
- **determine_basal.py mirrors the JS.** The original JS lines stay as `#//` comments beside the Python; `console_error()` and `round_basal()` exist so the emitted text matches AAPS's consoleError, `typeof()` and `convert_bg()` are semantic ports. Emulator-only parameters: `thisTime` (historical epoch ms instead of `new Date()`), `Fcasts` (dict the function fills with per-factor autoISF ratios, `emulISF`, `emuliobTH`, prediction arrays and `Levels`), `Flows` (list of `dict(title, indent, adr)` boxes rendered as the flowchart; `adr` is a hand-maintained reference to a JS line such as `'884+1'` or a helper such as `'sTB_32'`), `emulAI_ratio` (the core's per-loop list, appended in place by `autoISF()`). `profile['autoISF_version']` is compared lexically (`>= '3.1.0'`); `profile['new_parameter']['AAPS_Version']` is only ever tested for equality against `'<2.7'` and `'2.7'`, so `'3.3'` takes the fall-through path everywhere. The port is autoISF 3.2.0 while the user's phone runs 3.2.1 (extra echo lines such as `Sensitivity ratio unchanged`), so small transcript differences are expected.
- **Reason and consoleError wording is load-bearing.** `TreatLoop` text-scrapes the original SMB/maxBolus from the original `reason` and the emulated ones from the reason `determine_basal.py` returns (`'Microbolusing ...U'`, `'maxBolus'`); change that wording and the SMB columns silently read 0. The original ISF and autoISF ratio come from consoleError lines (`'ISF unchanged:'`, `'profile.sens:'`, `'final ISF factor is'`, `'currenttemp: ... lastTempAge:'`, `'maxBolus:'`) parsed by `PrepareSMB()` (pre-3.3 logs) or `scanConsoleError()` (3.3+, Nightscout); on 3.3+ and Nightscout `variable_sens` from the result overrides the ISF scrape (a KeyError only occurs when `lastTempAge` is known and neither an ISF line nor `variable_sens` exists). On Nightscout `'Autosens ratio:'` is matched in `ns_source.NightscoutSource.autosens_ratio()`, carried forward across loops and also used as the sensitivity ratio of the temp-basal IOB. Emulated ISF values travel through `Fcasts`, never through text.
- **New profile / new_parameter keys need defaults.** `determine_basal.py` mostly indexes `profile[...]` directly and older logs lack newer keys, so a new key needs a fallback in the missing-key section of `setVariant()` (the `if 'key' not in profile:` block; `new_parameter` keys are assigned there unconditionally) or an `in profile` guard. On `nightscout-source` a profile key has three layers: the matching section of `ns_settings.json` (copied 1:1 by `ns_profile.profile_at()`, keys starting with `_` skipped), then `profile_history.changes` rewinds a key for loops before its `when`, then VDF rows override. A new key goes into the settings section plus the `setVariant()` fallback for the logfile path.
- **VDF files are Python.** Each row is `<group> <key> <expression> [### comment]`. Groups: `profile`, `new_parameter`, `glucose_status`, `iob_data`, `meal_data`, `autosens_data`, `currenttemp`, `state`, `temp` (scratch dict per pass), plus `STAIR`, `STAIR_BAS/CR/ISF/LTG/HTG`, `INTERPOL`, `POLYGON` for time- or value-dependent settings, which must be defined above the rows that use them. Expressions go through `sanitize_vdf_expr()` (`profile[min_bg]` becomes `profile['min_bg']`) and are `eval()`'d inside `setVariant()` with the already-parsed dicts in scope, so `profile['min_bg'] + 10` works; `state`/`new_parameter` rows may hold a `"quoted"` string instead. The file is re-read for every loop; the pre-scan applies only the first row and only if it is a `state`/`new_parameter` row. There is no comment-line syntax: a blank line or a `#rofile ...` row is written to the `.log` as "not actioned". Reference: "Documentation in English/Guide to VDF Files for the AAPS Emulator.pdf"; example at repo root: `Demo_Sports_Adaptations.vdf`.
- **Nightscout branch.** `software/NIGHTSCOUT_SOURCE.md` is the contract between the modules (where it and the code disagree, the code wins). `ns_source.NightscoutSource.load()` pulls entries, treatments (8 h look-back), devicestatus and the profile store through `ns_client.NightscoutClient` (stdlib urllib, per-UTC-day cache: a day file is final once the UTC day ended more than an hour ago, the current day is refetched after 5 min; backfills into an old day never appear until that day file is deleted or `--refresh` is used) and hands them to `ns_glucose.GlucoseHistory` (rebuilds `glucose_status` from the Kalman-smoothed loop values on a 5-min grid, incl. dura_ISF and the parabola fit), `ns_iob.IobCalculator` (AAPS exponential insulin model over boluses and temp basals: `iob_array` with zero-temp variant, `currenttemp`, `lastTemp`, `lastBolusTime`; gets devicestatus to recover the planned end of a running temp) and `ns_profile.ProfileBuilder` (profile store + temp targets + profile switches, settings sections copied into `profile`, `profile_history` applied by time, consoleError activity-monitor line turned into synthetic step counts because Nightscout has no step data; degrades silently to the profile's fixed utcOffset without `zoneinfo`). `loops()` adds what `devicestatus` carries directly: the original result record, COB, the consoleError list, and values scraped from it. `emulator_core.scanNightscout()` forces `AAPS_Version='3.3'` and pushes each loop through `apply_glucose_status()` and `scanConsoleError()` (both split out for this branch) plus the unchanged collectors, then `TreatLoop`. The `ns_*` modules are deliberately stdlib-only (they also run on the phone). `ns_settings.json` holds the personal Nightscout URL and the AAPS preferences Nightscout does not carry, with `_assumed` naming the values that were inferred rather than exported (e.g. `low_temptarget_lowers_sensitivity` is kept off although the export says on, because the phone never entered resistance mode at TT 5.5); `aaps_preferences.json` is a scrubbed reference copy no module reads. Never put `token`/`api_secret_sha1` values or the export password into the committed copies. Sweeps over many VDFs run through `emulator_optimize.py` (calls `parameters_known` per variant with `noplot`).

## Conventions and traps

- **Line endings differ per file.** Upstream's format is CRLF: `determine_basal.py`, `emulator_GUI.py`, `*.config`, `change_log.md` and the root demo VDF still are. On `nightscout-source`, `emulator_core.py` and `emulator_batch.py` were re-saved as LF (commit 011a493) and all `ns_*`, `variants/` and `NIGHTSCOUT_SOURCE.md` files are LF. Nothing enforces this (no `.gitattributes`); preserve whatever a file has, and diff the two converted files against upstream with `--ignore-all-space`.
- **Version stamps instead of tags.** The four legacy scripts have `get_version_batch/GUI/core/determine_basal()` returning a `'YYYY-MM-DD HH:MM'` string with a trailing comment naming the change. Bump it when you change one of them and keep the previous line commented as `#cho_msg[...]`. The stamps are echoed into every result `.log`. The `ns_*` modules have no stamp. `change_log.md` is newest-first: a `DD.Mon.YYYY` line underlined with dashes, then prose.
- **Dead code comes in two forms:** ordinary `#`-prefixed lines, and lines disabled by deleting their first character so they stay column-aligned (`#cho_msg`, `#rofile`, `#lif`, `#f len(...)`). Grep for the truncated keyword too.
- **No `__main__` guards** in the four legacy scripts: importing `emulator_GUI.py` opens a Tk window; importing `emulator_batch.py` runs Android detection, argv parsing, the whole replay and `sys.exit()`. Import `emulator_core`/`determine_basal` instead. Only the `ns_*.py` modules have guards.
- German identifiers and comments in `emulator_core.py` (`hole(sLine, Ab, Auf, Zu)`, `zeile`, `wo`) stay as they are to keep upstream whole-file diffs readable.
- `parser_debug = True` at the top of `emulator_core.py` makes `scanLogfile()` append two records per log line to `/tmp/emulator_parser_debug.log`. Set it to `False` for long logfile runs.
- Batch exit status is 0 after `SYNTAX`, `UTF8` and `Z` alike (bare `sys.exit()`), and the sentinel itself is never printed; look for the `sub_issue()` message in the output, not `$?`.
- Docs: the root-level 2022 PDFs describe old scripts; under "Documentation in English" the Installation Guide (2025) and "The AAPS Logfile System" (2026) are current, the rest mostly predates the current arguments. `NIGHTSCOUT_SOURCE.md` and the README section document the Nightscout path.
